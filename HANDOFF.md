## WebGL room migration (from 2026-09-26) — READ FIRST if continuing it
Full report with screenshots: https://claude.ai/artifact/3CiUA3Qrg7azWwTLWSmqvN. Memory: `project-portfolio-webgl-poc.md`, `reference-portfolio-chrome-3d-room.md`.

**Why.** Home's room (`components/DeskScene.tsx`, CSS 3D planes up to 3225 px, `preserve-3d`) flashed/checkerboarded in Chrome on camera moves. Measured (CDP traces, DPR 2, M4 Pro): `TileBasedLayerImpl::AppendQuads checkerboard` + "tile violates memory policy"; up to 622 MB tiles, 298 layers, 110 checkerboard frames per Profile→Off Duty. Every CSS fix was measured and failed (visibility hiding, will-change, splitting planes, masks — any opacity animation repaints planes). Kate: CSS 3D not optimised further.
**POC** (`~/Documents/portfolio-offload/webgl-poc/`): three.js quads from an export of the CSS DOM, no flashes, p95 8.8 ms. **Spike hidden DOM** (CSS scene kept transparent for hit-testing): 189 layers, 204 MB tiles, 138 ms hitches → NO-GO. Only `display:none` of the CSS scene is cheap.
**Architecture (accepted).** WebGL draws the room; during any camera move only WebGL draws; at a stop only flat DOM of that stop (no CSS 3D). At home at rest the case, flip clock and lamp stay the page's flat DOM; when the camera leaves they are mirrored into WebGL (`components/room/mirror.ts`) in the same frame the DOM hides; handed back when home and still. Interactions = raycasting + flat accessible DOM controls projected over objects (`hits.ts`). Fallback idea (not built): per-stop stills + the same DOM overlay, no second renderer.

**Where.** Worktree `~/Documents/portfolio-webgl`, branch `webgl` off staging `69a9c4e` (not pushed, not merged). Commits: `169dc98` M1, `75c94be` M2, `e9dbc54` M3 spike (+ this handoff). Flag: `?gl=1` (sessionStorage; `?gl=0` off; `&tex=webp`, `&pr=1`). Legacy CSS room is the default. Server: `scripts/room/serve.sh 3301` (`next start`; preview_start hit the 5-server limit). Rebuild `npx next build` then restart serve.sh — `next start` does not see new public files without restart.
**Code.** `components/room/engine.ts` (renderer, camera driven by html `data-desk/-focus/-arrived` + scene-cam `--dx --dy --pan`, CSS-like transitions, texture slots/zones/prewarm/previews/poster, flight waits ≤1.5 s for textures), `mirror.ts`, `blur.ts` (GPU blur for drop-shadow/blur), `hits.ts`, `RoomGL.tsx`, `room.css`; `lib/room/pose.ts` (camera math shared with node scripts), `sig.ts`, `flag.ts`. Legacy touched minimally: boot script in `app/layout.tsx`, `room:arrive` listener in `useDeskCamera`, `DeskLamp flat`, `div.room-poster` + gl branch in `components/home/Home.tsx`.
**Data pipeline** (run against the legacy page on :3301): `scripts/room/bake.mjs` (+`collect.mjs`, `stitch.py`) → `public/room/scene.json` + `tex/*.webp`, masters in `~/Documents/portfolio-offload/room-bake/png`; `textures.mjs` (+`prep.py`, `--shard=i/6` in parallel, then one plain run for metadata) → `public/room/ktx2`, `lo/`; `poster.mjs` → `poster-home.webp`; `hits.mjs` → `hits.json`. Re-running bake rewrites scene.json: re-run textures.mjs after it.
**Tests/benchmarks.** `check-stops.mjs` (camera vs CSS geometry), `compare.mjs` + `diff.py` (CSS vs GL screenshots), `bench.mjs` (headed, real GPU; `MOBILE=1`), `flash.mjs` + `flashes.py`, `cold.mjs` (`SLOW=1`), `nav-test.mjs`, `hits-test.mjs`. Results: `~/Documents/portfolio-offload/webgl-m1/` (bench/*.json, compare*, flash-*), `webgl-m2/` (cold-*.json, compare-*), `webgl-m3/`.
**Baselines** (1512×860 @2, 120 Hz): GL flights p95 ≤10 ms, max ≤17 ms, 0 >33 ms at PR 1/1.5/2 (CSS: p95 75, max 767, 213 >33); 0 flashes (CSS 4); home swap ≤0.5 px; GL within 0.5 px of exact geometry. On a fail: stop the dependent work, record why, do independent prep. Don't tune benchmarks to pass; document visual differences, don't fix them by changing the design.
