### 2. Why the migration (do not reopen)
- **Problem:** the CSS 3D room (planes up to 3225 px, `preserve-3d`) flashed / checkerboarded in Chrome on camera moves (retina, M4 Pro, DPR 2). CDP traces: `TileBasedLayerImpl::AppendQuads checkerboard` + "tile violates memory policy"; per Profile→Off Duty flight up to **110 checkerboard frames, 622 MB of tiles, 298 layers**. Legacy bench: flights p95 up to **75 ms, max 767 ms, 213 frames >33 ms**, 4 visible flashes in a screencast.
- **CSS fixes measured and failed (25–26.09):** per-stop visibility hiding / route-aware hiding (−30 % at best), `will-change` (worse), splitting planes (Chrome culled whole pieces), removing chalk/grid effects/extensions, baked `<img>` tiles, a gentler camera curve (`.45,0,.55,1`, 2.3 s + 0.2 s wait — helped, did not fix; it varies with GPU memory), direct vs hub route, masks (a 75 % mask still flashed; **any opacity animation repaints the planes every main frame, +~100 frames / +25 % raster**; only instant toggles are free). Kate: CSS 3D is not optimised further. Details: memory `reference-portfolio-chrome-3d-room.md`, benches `~/Documents/portfolio-offload/perf-bench/`.
- **Three.js POC** (`~/Documents/portfolio-offload/webgl-poc/`): quads exported from the live CSS DOM (222 items, 127 textures), camera = inverse of the CSS transform; **no flashes; PR 2 avg 8.3 ms, p95 8.8, max 9.3, 0 frames >20 ms** (one 83 ms hitch on first flight = lazy texture upload → pre-upload). Texture budget then 334 MB RGBA → KTX2 43–77 MB.
- **Spike "hidden CSS scene + WebGL"** (`spike.mjs`, `spike_1..3.json`): keeping the CSS scene transparent for hit-testing still had **189 layers, 204 MB tiles, WebGL hitches to 138 ms**; only `display:none` of the CSS scene was cheap (8 layers, 15 MB, WebGL p95 8.8 / max 9.3). Reading 74 animated matrices per frame: 1.2 ms. **Verdict: DOM-as-interaction-layer / hidden CSS scene is NO-GO.**
- **Therefore:** full WebGL renderer for the room + a lightweight *flat* (non-3D) DOM layer for what must be DOM (controls/a11y, text, video, the case at home). **Do not propose CSS 3D tuning or a hidden CSS scene again.**
